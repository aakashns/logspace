# Webapp Agent Guide

This app was scaffolded with `remix new`. Use these conventions when continuing to build it out.

## Commands

```sh
npm i
npm run dev
npm run hmr
npm run start
npm test
npm run typecheck
npm run lint
npm run format
```

`npm run lint` runs oxlint (`.oxlintrc.json`) and `npm run format` formats everything with oxfmt (`.oxfmtrc.json`: no semicolons, single quotes, 100-character lines); `npm run format:check` checks formatting without writing.

Use `npm run hmr` for live server and browser updates; `npm run dev` only watches and restarts the server. `npm run start` runs in production mode without a separate build step.

## Browser Tools

Always use Playwright or the in-app browser (when available) for browser automation, screenshots, and visual verification. Do not invoke a browser directly through its command-line interface.

## Pull Requests

To show screenshots or videos in a pull request, attach them with `gh pr create --attach './shot.png#Alt text'` (repeatable) and reference them in the body as `![Alt text](./shot.png)`; gh uploads them and rewrites the links. Never commit or push images to the repo, not even on a separate branch, just to show them in a pull request.

## Starter Layout

- `app/routes.ts` defines the shared route contract used by server and browser modules for type-safe hrefs
- `app/router.ts` wires routes to controllers and installs the standard Remix component renderer used by actions
- Put top-level route actions in `app/actions/controller.tsx`; add `app/actions/<route-key>/controller.tsx` for nested route maps. `app/actions/controller.test.ts` is the root controller's router smoke test
- `app/actions/document.tsx` renders the HTML document shell. Pages pass it their main image as `preloadImage` (`getPriorityImage` in `app/ui/post.tsx`), preloaded first thing in `<head>`, before the inlined stylesheet. Its scripts only make the navbar and share buttons interactive, so an inline script adds them (and the entry's modulepreloads) on the window's `load` event: Caddy's HTTP/2 ignores request priorities, so loading them earlier slows the page's photos. Remix's own modulepreloads for client entries stay, since they're requested after the preloaded image and dropping them delays hydration
- `app/actions/public/` contains the browser runtime entry, the theme toggle, and the global CSS:
  - `global.css` declares layer order `reset, theme, rmx` and imports the rest. It's linked from the document in development and inlined into it, with imports flattened, everywhere else (see `globalStylesheet` in `app/assets.ts`)
  - `reset.css`
  - `theme.css` starts with the self-hosted Instrument Sans `@font-face` rules for headings; body text and code use the system UI and monospace fonts. The files live in root `public/fonts/`. Headings only use weight 600, so the Instrument Sans files are static weight-600 instances, and the Latin one is embedded in the inlined stylesheet as a data URL (`EMBEDDED_FONTS` in `app/assets.ts`) so headings render in it from the first paint with no font swap. Don't rely on `font-display: optional` to prevent swaps: Safari picks up a late font when Remix adopts its server-rendered styles. After the rules come shadcn-style tokens as CSS variables on `:root`. Colors are written as `light-dark(<light>, <dark>)` and resolved by `color-scheme`: the `light`/`dark` class the server renders on `<html>` from the `theme` cookie, else the system preference. Fonts are `--font-sans` for body, `--font-heading` for headings, and `--font-mono` for code. Use the `var(--…)` tokens for colors and fonts instead of hardcoding them
- Posts are stored in SQLite, read by `app/data/posts.ts`, and written and edited at `/admin`. What a post is made of, which `parsePost` checks and the `/admin` form follows, is in `docs/posts.md`; keep the two in step. An article's body is stored in its own `article_body` column, for search. Captions are Markdown, rendered by `app/lib/caption.ts`; articles by `app/data/article.ts`. Post pages are `app/actions/posts/`, and the feed and post UI are in `app/ui/`. Tests seed an in-memory database and memory media storage with the sample posts in `test/content/` (one of each post type, with an article's body in its `article.md`) by calling `seedDatabase()` and `seedMedia()` from `test/seed.ts` in `beforeAll`
- Post media (photos, videos, posters, covers) is in `remix/file-storage`, under keys `posts/<id>/<file>`, and `app/data/media.ts` owns it: it picks the backend from `MEDIA_STORAGE` (`fs` with `MEDIA_DIR`, the default; `s3` for S3 or Cloudflare R2, with the `MEDIA_S3_*` settings; `memory`, which `npm test` uses) and has every read and write (`getPostFile`, `hasPostFile`, `listPostFiles`, `savePostFile`, `deletePostFiles`). Don't touch media on disk directly: the `/posts/:id/*file` route serves `getPostFile` with `createFileResponse` (ranges, Content-Type, ETag, an hour's cache), saving a post checks `hasPostFile`, and articles find video posters with `hasPostFile` on the names a poster can have, since the fs backend's `list()` reads every file's metadata (so `listPostFiles` is only for the `/admin` form). `savePostFile` sets a file's name and type from the name it's saved as, never from the file, and uploads are limited to photos and videos (`isUploadableFileName`, no SVG) since files are served inline from the site's origin. `savePostFile` also records each image's upright size and a content hash in the `post_images` table (no foreign key, since a new post's files are saved before it is), which `getPostImages` reads when posts are loaded: photos get their `width`/`height` from it (a post only gives a video's size, which defaults to its poster's), and their URLs get `?v=<hash>`, plus `&w=<width>` for the resized WebP copies in `srcset`. `app/data/images.ts` has the sharp code and the widths (`IMAGE_WIDTHS`); `getPostImageVariant` makes a copy the first time it's asked for and keeps it in storage under `variants/<id>/<file>/`, which replacing or deleting the file removes. The file route caches a URL with the current `v` for a year (`immutable`), since a changed file gets a new one. Give `<img>`s of post photos `srcset` with `sizes` (`FULL_WIDTH_IMAGE_SIZES` or `HALF_WIDTH_IMAGE_SIZES` in `app/lib/constants.ts`), and keep link previews on the uploaded file (`src`, `posterImage`), which some sites can't show as WebP. `MEDIA_DIR` is outside the repo (`/var/lib/logspace/media` in production; locally set in `.env`); without it, media goes in the git-ignored `media/`
- `app/data/db.ts` opens the database and runs migrations from `db/migrations/` at startup, and `app/data/tables.ts` defines the tables to match. The database file is `DATABASE_PATH`, kept outside the repo so `git clean -x` can't delete it (`/var/lib/logspace/app.sqlite` in production; locally set in `.env`); without it, `db.ts` falls back to the git-ignored `db/app.sqlite`
- `/admin` (`app/actions/admin/`) is protected by one admin password, `ADMIN_PASSWORD`, with an `admin_session` cookie signed by `AUTH_SESSION_SECRET` (meant for every session cookie the site sets, including a future user login) and scoped to `/admin`; `auth.ts` owns the checks, and `middleware.ts` has the middleware every `/admin` controller uses, including `formData()` with the upload limits (`MAX_UPLOAD_*` in `app/lib/constants.ts`) and a 413 page for forms over them. `/admin/posts/new` and `/admin/posts/:id/edit` (`app/actions/admin/posts/`) share one multipart form: `post-form.tsx` is the page, built from the generic inputs in `fields.tsx`, the fields every post has (and the post's file list) in `post-fields.tsx`, each type's fields in `type-fields.tsx`, `issue-list.tsx`, and `delete-post.tsx`. `form-values.ts` reads a submission (`readPostForm`: each media field is a file name or a file chosen next to it, plus the Add photos and article body uploads), saves its uploads (`savePostUploads`, before validating, so a rejected form keeps them, but never for a new post form whose id is already published), and checks it with `parsePost` and that its files are in media storage. A post's type is fixed once it's created. The edit page's Delete button opens a native `<dialog>` (via `command`/`commandfor`, no JavaScript) that posts to `/admin/posts/:id/delete`, which deletes the post and then its files in media storage (`deletePostFiles`). Locally both secrets come from `.env`; in production from `/etc/logspace.env` (see the repo README). `cop()` in the router rejects cross-site form posts
- Remix's client-side navigation diffs `<head>` by `data-rmx-key`, so give every element there a stable `data-rmx-key`, and add `data-rmx-preserve-dom` to stylesheets; otherwise a navigation can re-insert the stylesheet and flash unstyled content
- Each `css()` style is its own cascade layer inside `rmx`, ordered by first use, and a later layer wins whatever the selectors' specificity. So a parent's nested rule (`'& [data-x]'`) can't override a child's own `css()`; put such rules in the child's style. Nested selectors must start with `&` (others are dropped), so a condition on an ancestor goes in `:is()`, e.g. `'&:is(form:has(:checked) *)'`
- `/rss.xml` (`app/lib/rss.ts`) is an RSS 2.0 feed of the newest `FEED_LENGTH` posts, each with its whole content as HTML with absolute URLs; every page links to it in `<head>` for feed readers to find, and from the navbar (`app/ui/rss-link.tsx`, with `data-rmx-document` so the browser opens the XML rather than client-side navigation)
- What's particular to the site (its title, URL, description, the home page's heading and subheading, and its logo, icon, and social preview image) is its config, set at `/admin/config` (`app/actions/admin/config/`) and stored in the `config` table, one row per saved setting. The title, URL, and description are required and have no default: until they're saved the site isn't configured (`isSiteConfigured()`), so the `requireSiteConfig()` middleware sends every public page to `/admin/login` (302) and answers `/rss.xml`, `/sitemap.xml`, `/robots.txt`, and `/site.webmanifest` with a 503, leaving alone `/admin/*`, `/assets/*`, the site's images (`/favicon.ico`, `/apple-touch-icon.png`, `/site/*`), and `public/` (served before it). `/admin` then leads to `/admin/config`, which fills in an empty site URL with the request's origin. Any other setting that was never saved has its default (`DEFAULT_SITE_CONFIG`). `app/data/config.ts` owns it: it's kept in memory, and the `siteConfig()` middleware (`app/middleware/site-config.ts`) waits for the first read only; after that each request starts a re-read from the database in the background without waiting for it (at most one at a time; a failed one is logged and keeps the last good copy; one that started before a save is dropped), so a request sees the config at most one read behind the database, and changes made by another process or directly in the database take effect without a restart. `saveSiteConfig` updates the copy at once. Code that runs for a request reads it synchronously: `getSiteConfig()` returns the full config and throws if the site isn't configured, so it's for public pages, the RSS feed, the sitemap, `/robots.txt`, and `/site.webmanifest` (routes, not files in `public/`); code that also runs on the admin pages before then (`Document`, `/admin/config`, the site's image files) uses `getSavedSiteConfig()`, whose required settings can be missing (`Document` falls back to `APP_NAME` for the title). Use it instead of hardcoding anything about the site's owner: this app is LogSpace, which anyone can run for their own site. Tests run with `TEST_SITE_CONFIG` from `test/seed.ts`, which `seedDatabase()` saves; a test file that doesn't call it has a fresh, unconfigured database
- The site's images are uploaded at `/admin/config` and owned by `app/data/site-images.ts`. `processSiteImage` turns an upload into the files the site serves (SVGs are drawn as PNGs with sharp, so no SVG is ever served from the site's origin), which are stored in media storage under `site/<file>` once the whole form is valid, and the config keeps each image's file, size, and content hash. The logo (`app/ui/site-logo.tsx`) is a CSS mask filled with `currentColor` so it follows the theme, and the navbar shows the site title instead when there's none. One square icon makes `favicon.ico` (a PNG inside an ICO), `apple-touch-icon.png` (both served at the root, where browsers and crawlers look for them whatever the page links), and `/site/icon-192.png`, `icon-512.png`, and `icon-maskable-512.png` (for the manifest); without one they're made from LogSpace's mark, `DEFAULT_ICON_SVG`. The favicon and the two plain icons keep any transparency; `apple-touch-icon.png` and the maskable icon, which can't have it, are on the icon's own background color, the most common color among its opaque pixels (`FALLBACK_ICON_BACKGROUND` if it has none), which the icon's `SiteImage` keeps as `color` for the manifest's `theme_color` and `background_color` (`getIconColor`). `/admin/config` shows the logo and icon previews on a checkerboard so their transparency shows. Pages without an image of their own use the social preview image for link previews, or have none. Link to them with `getIconHref` and `getSiteImageHref`, whose `?v=<hash>` URLs are cached for a year, so a new upload needs no version bump
- `app/lib/constants.ts` holds app-wide constants (e.g. `FEED_LENGTH`); add new constants here instead of inlining them
- `app/assets.ts` owns the server-side asset pipeline used by the asset route and render middleware; outside development asset URLs are fingerprinted and cached for a year
- `app/middleware/security-headers.ts` adds HSTS, COOP, frame and sniffing protection headers to every response
- Root `public/` contains static files served unchanged from the app root; `public/fonts/` is served with a one-year immutable cache, so give a changed font file a new name
- `scripts/` (at the repo root) has the deployment: `install.sh <domain> [<redirected domain>...]` fills in the templates `logspace.service` and `Caddyfile` and installs them, and `set-admin-password.sh` sets `ADMIN_PASSWORD`. Keep anything specific to one site out of them

This starter intentionally begins small; add directories like `app/data/`, `app/middleware/`, `app/ui/`, and `test/` only when you need them.
